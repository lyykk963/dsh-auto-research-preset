# 幻灯片设计契约（反 AI 感 / 反单调 / 必配图）— v9.4

> 触发：2026-10-18 用户反馈"PPT 太有 AI 感、单调、没图"。
> 诊断结论：**模板资产是好的**（15 套 / 591.7 MB，实测 15/15 可用），
> 病灶在**流程**——原 `ppt-workflow.md` 的四步（场景/配色/字体/页数）里**没有任何一步规定"图"**，
> 全文 143 行只有"图题 14–16pt"这一行字号表提到图。于是产出必然退化成满页 bullet。
> 本契约补上三件事：**图规划**、**反 AI 感红线**、**可机检的体检**。

## 0. 一页纸原则

> 每页只证明一个论点；标题写**结论句**，不写名词短语；**没有视觉元素的页不超过一半**。

## 1. 反 AI 感十二条红线（Hard Rules）

| # | 红线 | 为什么（这是 AI 感的具体来源） |
|---|------|-------------------------------|
| 1 | 每页要点 **≤4 条**，每条 **≤20 字** | 满页等长 bullet 是 AI 感第一来源 |
| 2 | 全篇至少 **3 种构图**（图左文右 / 通栏图 / 双栏对比 / 图表页 / 大数字页） | 一种版式从头到尾 = 单调 |
| 3 | **每 3 页至少 1 个视觉元素**（数据图 / 示意图 / 表格 / 截图） | "没图"是最容易被一眼看穿的短板 |
| 4 | 一页出现 **≥3 个可比数字 → 必须转图或表** | 数字堆在句子里，读者无法比较 |
| 5 | 标题**不许用 emoji**、不许"XX：YY：ZZ"多重冒号套路 | 套路化标题是模板腔 |
| 6 | 标题必须是**结论句**（如"3 月出现增速抬升，但仅一半来自新进"），不是"主要发现" | 名词短语标题=没有信息量 |
| 7 | 留白 **≥25%**；不许把内容区填满 | 塞满=没有呼吸感，是"AI 排版"的特征 |
| 8 | 主色 **≤3**（模板主色 + 1 强调色）；不许彩虹配色 | 多色=廉价 |
| 9 | 强调靠**位置/大小/对比**，不靠"全加粗 + 红字" | 到处强调=无处强调 |
| 10 | 不许出现"谢谢聆听"之外的空白页；每节开场用 **90pt 大数字 + 一句结论** | 空过渡页是最典型的模板化 |
| 11 | 图必须有**来源与单位**；示意图与实拍图不混用 | 无源图 = 不可核 |
| 12 | 中英混排时：数字/英文用 Times New Roman 或 Arial，中文用微软雅黑 | 字体混乱是廉价感来源 |

## 2. 生成前强制多一步：图规划（五步，不是四步）

原四步（场景 → 配色 → 字体 → 页数/布局）之后，**必须**补第五步并落到表里：

```
Step 5 · 图规划：逐页填下表，填不出"视觉类型"的页 → 要么合并，要么改成图
```

| 页 | 标题（结论句） | 视觉类型 | 来源 / 生成方式 | 是否已产出 |
|----|---------------|----------|-----------------|-----------|
| 1 | 封面 | 无（模板封面） | 模板 | — |
| 2 | 目录/路线 | 图标化数字 | 模板 | — |
| 3 | 论点 A | **数据图**（折线/柱/散点） | `matplotlib` + `tools/generate_figure.py` 或 `scientific-visualization` | ☐ |
| 4 | 论点 B | **示意图**（机制/流程） | `autofigure` / `baoyu-diagram` / `scientific-schematics` | ☐ |
| 5 | 论点 C | **对比表** | 报告里的证据表 | ☐ |

**判定**：一页若既无图也无表也无图表，**必须在 `parking-lot` 里写理由**（例如纯概念定义页），
且全篇这类页 ≤50%——否则触发 §3 的机检 FAIL。

### 视觉类型的默认选择

| 数据形态 | 用哪种图 | 工具 |
|---------|---------|------|
| 时间序列 / 趋势 | 折线（带基准线与标注） | `matplotlib` + 预设 `.mplstyle` |
| 分组比较（≥3 组） | 横向条形图（优于柱状，标签可读） | 同上 |
| 两变量关系 | 散点（带拟合与 n） | 同上 |
| 流程 / 机制 / 体系结构 | 示意图（矢量） | `autofigure`（SVG）或 `baoyu-diagram` |
| 概念对比 / 参数清单 | 表格（booktabs 风格，去竖线） | PPTD 表格或 `table-generation` |
| 单一关键数字 | 大数字页（90pt）+ 一句结论 | 模板 |

## 3. 产出后体检（可机检，不靠感觉）

```bash
python tools/check_deck.py <deck.pptx>          # 详细
python tools/check_deck.py <deck.pptx> --quiet  # 只出结论行，给流程调用
```

四个指标：**纯文字页占比** / **图形对象数** / **平均每页字数** / **构图多样性**。

判据（默认，场景可调）：
- **FAIL**：纯文字页 >50%，或 图形对象 < ⌈页数/4⌉
- **WARN**：平均每页 >260 字，或 构图多样性 <30%，或 连续同构图 >4 页

> 2026-10-18 对照实测：设计模板（白蓝色系·国自然）= **PASS**（纯文字页 12%、53 个图形、构图多样性 47%）；
> 朴素生成的"AI 感"deck = **FAIL**（纯文字页 100%、0 个图形）。**这个检查能把两者分开。**

机检只查"结构层"；**视觉层必须人看一眼**（渲染后截图）：字号层级是否清楚、图与论点是否匹配、留白是否够。

## 4. 与既有流程的接线

```
Step 1–4（ppt-workflow.md §1） → Step 5 图规划（本契约 §2）
  → 按索引选模板（ppt-workflow.md §2）
  → pptd_import → 编辑 → pptd_check → pptd_render
  → check_deck 体检（§3）→ 不 PASS 不得交付
```

**铁律**：`check_deck` 不替代人眼；它只保证"不会交出一份纯文字、没图、构图单一的 deck"。

## 5. 已知局限（不得假装没有）

1. `check_deck` 只统计**结构**，看不懂"这张图是否支撑该页论点"——那仍需独立评审。
2. 模板多为 27–130 MB 的重型 pptx。**实测（2026-10-18）**：白蓝色系 6.5 MB / 17 页 / 643 个可编辑元素，`pptd_import` 成功（396 项标准化、2 项资源占位），`pptd_check` → `pptd_render` 全通过。更重的 27–130 MB 未测。
3. **`ppt_template_create_project` 需要用户在 DSH 界面里先点选模板**；未选择时报"请先选择要使用的模板"。无 GUI 选择时，只能走 `pptd_import` 已有 pptx 的路径。
3. 论文答辩 / 人才申报场景**仍为 0 套模板**（融合研究侧目录为空），只能走 DSH 设计模板或用户自备。
