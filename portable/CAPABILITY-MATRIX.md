# 能力矩阵：搬到哪里还剩多少「满血」

> 定义先说清：**「满血」= 方法论 + 契约 + 可机检工具 + 独立评审**。
> 面板、自动续跑、技能路由是 **UX 增强**，丢了不等于残血，但要说清丢了什么。

## 1. 四层能力，逐层看

| 层 | 内容 | 依赖宿主吗 |
|---|---|---|
| L1 方法论 | 六阶段流程、质量门 G1–G11、证据门、写作红线、创新三阶 | **不依赖**，纯文档 |
| L2 契约 | 13 份 contracts（验收门/引用纪律/PPT/幻灯片设计/评审独立性/评审留痕…） | **不依赖** |
| L3 工具 | claims / prereg / delivery / fetch / claimlog / check_deck / stage_gate / selfcheck … | 只需 Python 3.8+（**纯标准库**） |
| L4 编排 | 进度面板、goal 自动续跑、技能路由、子代理评审 | **强依赖宿主** |

## 3. 最要紧的一条：独立评审不能"自己评自己"

本方法论的红线是「**被评者不得打分**」。所以在**不能起独立子代理**的宿主上：

- 仍然可以做 L1–L3 的全部机检（claims / prereg / delivery / deck 体检）；
- 但**质量验收降级为 DRIVE-only**：只能证明"没犯机械错"，不能声称"质量通过"；
- 交付时必须写明：`质量门：DRIVE only（宿主无独立评审能力）`。

这不是抠字眼——2026-10-17 那次交付里，一条改变结论的错误（模型比较样本 17 点却说 16 个月）
就是**机检 11/11 全过、独立评审才抓出来**的。

## 4. 结论

- **要在别的 AI 上"尽量满血"**：优先选**能起独立子代理**的宿主（Claude Code、DSH、Codex）。
- **只要方法+机检**：任何能读文件、能跑 Python 的宿主都行（Cursor/Trae/甚至纯 CLI）。
- **面板与续跑**：只有 DSH 原生支持；其他宿主用「进度文件 + PLAN.md」等价替代。
